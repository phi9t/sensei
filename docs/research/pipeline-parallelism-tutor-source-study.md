# Pipeline Parallelism Tutor: source study

## Scope and provenance

This study describes [`ezyang/pipeline-parallelism-tutor`](https://github.com/ezyang/pipeline-parallelism-tutor) from its own source, tests, README, GitHub repository metadata, and license metadata only. It does not follow or use the papers and websites linked by the project. Consequently, names such as GPipe, 1F1B, ZB-H1/H2, BF-PP, and ZeroPP below describe how this repository models or labels those schedules; they are not an independent verification of the underlying papers.

The immutable source pin is **`4cf0b7247ee9334a3795af746dfd745fb5562601`**, resolved on 2026-08-19 from symbolic `HEAD` to the default branch `main`. GitHub's repository metadata also reported `default_branch: main`; its commit metadata dates this head to 2026-08-17. All code citations below are commit-pinned.

License status matters for reuse: the pinned tree contains no license file, GitHub repository metadata reports `license: null`, and GitHub's license endpoint returns 404. The code is publicly readable, but this evidence does **not** establish permission to copy, modify, or redistribute it. Reuse the ideas; seek clarification before reusing implementation text or code.

At intern level, the program is a dependency-aware scheduling board. A model is cut into stages, a training batch into microbatches, and each colored block is forward (`F`), backward/input-gradient (`B`), or optionally weight-gradient (`W`) work. The learner places one block at a time on rank timelines. The engine rejects impossible moves, shows where memory accumulates, and compares the result with a policy-generated reference schedule ([README lines 1-6](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L1-L6)).

## Runtime/game loop

The runtime is best understood as a replayable state machine wrapped in a teaching loop.

1. **Load a lesson.** `loadLevel` replays any supplied actions, independently projects the reference policy, clears transient UI state, and then renders ([app lines 101-123](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L101-L123)).
2. **Select an action.** A learner chooses an operation or idle on one rank. State is an action log; replaying a prefix is the undo/redo mechanism ([engine lines 95-118](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L95-L118), [lines 264-267](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L264-L267)).
3. **Validate and apply.** `apply` checks that the operation exists, belongs to the selected rank, has satisfied dependencies, and fits memory. Illegal moves throw an error carrying a structured reason; legal moves update placement, lane frontier, in-flight activations, phase markers, FSDP residency, and the action log ([engine lines 206-260](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L206-L260)).
4. **Render consequences.** The browser redraws grid, picker, stats, controls, and comparison; free-edit mode swaps in a separate grid and validation chrome ([app lines 539-552](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L539-L552)).
5. **Escalate assistance on demand.** A policy can choose one operation, auto-run until a new event type, or project to completion. Projection repeatedly advances the rank with the earliest frontier, inserts forced idle when necessary, reports ties/cap blocks/phase changes, and detects deadlock ([engine lines 374-445](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L374-L445)).
6. **Evaluate completion.** Score includes makespan, total work, utilization-derived bubble, internal bubble, peak memory, and all-gather count. The reference is not an optimizer: it is the projection of the configuration's “natural” policy—BF-PP with FSDP, zero-bubble for split gradients, otherwise GPipe without a cap or 1F1B with one ([engine lines 853-891](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L853-L891)).
7. **Turn the result into diagnosis.** A completed schedule may be recognized by per-rank operation order, traced backward along its critical path, compared on a common axis, and annotated with why each idle was forced or voluntary ([engine lines 1094-1143](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1094-L1143), [lines 1146-1200](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1146-L1200)).
8. **Persist and progress.** Browser storage records cleared levels and best solutions; the URL hash encodes level, sandbox configuration, and the full action sequence, making partial states reproducible ([app lines 25-43](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L25-L43), [lines 1811-1842](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L1811-L1842)).

This loop is deterministic enough to support undo, sharing, regression tests, and alternate UIs because the durable user artifact is not a screenshot or mutated grid; it is `(level configuration, ordered actions)`.

## Domain model and scheduling mechanics

### Schedule geometry

Configuration is small but expressive: `P` physical pipeline ranks, `V` virtual chunks per rank, `M` microbatches, an operation-duration model, and an optional activation-memory cap. The number of logical stages is `P × V` ([engine lines 4-9](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L4-L9), [lines 28-30](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L28-L30)). Time is discrete; an operation occupies a half-open integer interval `[start, start + duration)` ([engine lines 1-2](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1-L2)).

Stage placement has two explicit geometries. `wrap` maps stage `s` to `s mod P`, so a rank hosts stages `r, r+P, ...`. `v` reverses odd chunks, making the microbatch path bounce at pipe ends; it is the default when `V > 1` ([engine lines 32-54](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L32-L54)). The tests pin the distinction for `P=4,V=2`: V placement assigns `0,7 / 1,6 / 2,5 / 3,4`, while wrap assigns `0,4 / 1,5 / 2,6 / 3,7` ([tests lines 261-275](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/tests/engine.test.mjs#L261-L275)).

### Operations and dependency invariants

The engine materializes every `(kind, stage, microbatch)` tuple as an operation with a derived rank and duration ([engine lines 57-75](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L57-L75)). Its direct dependency DAG is deliberately compact:

- `F(s,m)` depends on `F(s-1,m)` unless it is the first stage.
- `B(s,m)` depends on the next stage's backward, or its own forward at the last stage; the engine also states the same-stage forward dependency explicitly for useful errors.
- `W(s,m)` depends on `B(s,m)`.

These rules are encoded in one function ([engine lines 77-93](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L77-L93)). An operation is ready only at its rank's frontier, after every direct predecessor has been placed and finished, and when memory admission succeeds ([engine lines 156-182](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L156-L182), [lines 197-200](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L197-L200)). Tests cover both an unscheduled predecessor and a predecessor finishing one slot too late ([tests lines 51-67](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/tests/engine.test.mjs#L51-L67)).

The model separates “construct only valid prefixes” from “edit an invalid plan toward validity.” Normal actions preserve invariants. Free-form plans can temporarily contain overlap, missing/late dependencies, and memory violations; `planViolations` diagnoses the whole plan before it can be canonicalized back into actions ([engine lines 476-490](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L476-L490), [tests lines 107-137](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/tests/engine.test.mjs#L107-L137)).

### Cost and memory models

The duration models are abstractions, not kernel simulators: uniform `F=1,B=1`; “honest” `F=1,B=2`; split-gradient `F=B=W=1`; and uneven split `F=1,B=2,W=1` ([engine lines 11-25](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L11-L25)). In a nonsplit model, `B` releases an activation; in a split model, `W` releases it because the weight-gradient operation still needs the saved activation ([engine lines 241-255](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L241-L255)).

Bubble is `1 - work/(P × makespan)`. “Internal bubble” instead measures idle only between each rank's first and last real operation, intentionally excluding fill/drain stagger ([engine lines 853-878](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L853-L878)). This makes the chosen metric part of the lesson: a parallelogram-shaped ZB-H2 schedule can score zero internal bubble while retaining nonzero naive bubble.

The FSDP lesson adds an intentionally greedy cache model. A stage's weights are gathered on first use, remain resident for reuse, and other weights are resharded for free when the cap forces eviction. Admission sums in-flight activations and resident weight units; it counts gather events but gives them no duration ([engine lines 121-145](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L121-L145), [lines 227-257](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L227-L257)). The executable scenario proves the repository's intended contrast: group size 4 completes with 10 all-gathers; group size 8 deadlocks under the cap; a per-microbatch 1F1B projection completes with at least twice as many gathers ([tests lines 473-489](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/tests/engine.test.mjs#L473-L489)).

### Policies are ordered heuristics, not optimal search

GPipe orders forwards before backwards. 1F1B orders backward before forward and uses a warmup quota. Zero-bubble uses `B > F > W` plus quota; BF-PP orders group-major, all forwards of a group before its backwards ([engine lines 281-296](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L281-L296), [lines 324-370](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L324-L370)). A policy ranks only the currently legal ready set; the global driver repeatedly chooses the earliest rank frontier ([engine lines 374-389](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L374-L389)).

This distinction prevents a common misreading of “par.” The repository itself supplies a counterexample: its ragged VPP lesson says the balanced-round Megatron reference scores 22 while a hand-crafted 21 exists; “par” is explicitly the lesson's schedule, not the optimum ([levels lines 121-137](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/levels.js#L121-L137)). Recognition is likewise structural but limited: completed schedules match canonical projections by each rank's operation **order**, not exact time slots ([engine lines 1146-1158](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1146-L1158)).

### Building blocks as a second representation

Beyond greedy placement, the engine represents a schedule as one microbatch trajectory repeated every per-rank work interval `w`. It states a tiling condition—distinct occupied residues modulo `w` on each rank—and derives steady-state activation peak from the trajectory's lifespan ([engine lines 894-904](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L894-L904), [lines 917-925](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L917-L925)). Tests show a single-microbatch 1F1B block stamping to a complete makespan-22 schedule with peak `[4,3,2,1]`, and a too-eager block violating a tight cap when stamped ([tests lines 216-258](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/tests/engine.test.mjs#L216-L258)). This is the deepest pedagogical shift in representation: learners move from placing isolated blocks to reasoning about periodic geometry and memory before expanding the schedule.

## UI/interaction pedagogy

The interface treats assistance as a ladder rather than a binary answer reveal. “Hard” shows errors, “normal” dims unavailable work, and “coach” suggests moves and previews consequences ([index lines 16-21](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/index.html#L16-L21)). The README then distinguishes validation, ready-set revelation, policy coaching, one-step automation, event-bounded automation, and full projection ([README lines 13-29](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L13-L29)). “Run until strange” is especially strong: automation stops at a novel tie, forced bubble, memory cap event, or phase transition, returning control at the conceptual boundary rather than after rote work ([engine lines 448-465](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L448-L465)).

The curriculum progressively discloses both concepts and UI power. The first lesson suppresses proposal ghosts; scoreboard appears with pipelining; coach, step, auto-run, and sandbox arrive at 1F1B; full projection arrives one level later ([app lines 9-23](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L9-L23)). The 11 levels then stage complexity from a two-rank, one-microbatch dependency puzzle through memory walls, 1F1B, periodic building blocks, VPP/ragged rounds, nonuniform backward cost, split gradients, deeper warmup, and FSDP weight residency ([levels lines 12-52](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/levels.js#L12-L52), [lines 140-204](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/levels.js#L140-L204)).

The interaction design makes causality inspectable in several complementary ways:

- Ghost blocks expose feasible next moves without committing them; future-slot clicks atomically pad intervening gaps with idle ([app lines 661-699](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L661-L699)).
- Hover tracing distinguishes prerequisites from operations unblocked downstream; completed idle slots explain their blocker or identify voluntary delay ([README lines 70-76](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L70-L76), [engine lines 1121-1143](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1121-L1143)).
- Thin memory strips externalize the otherwise hidden activation state; the FSDP lesson adds weight residency and gather ticks ([app lines 709-738](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L709-L738)).
- Free edit temporarily relaxes invariants, lists violations live, detects whether missing dependencies can still fit, and only commits a consistent plan ([app lines 862-891](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L862-L891), [lines 1134-1163](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L1134-L1163)).
- Completion feedback is analytical rather than merely celebratory: recognition names a matched schedule, critical path locates makespan gates and voluntary delays, and a reference comparison shares the time axis ([README lines 70-73](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L70-L73)).

For an MTS reader, the through-line is that the UI repeatedly maps a visible geometric symptom back to a machine-checkable invariant: a gap to an unsatisfied predecessor, an OOM to residency accounting, a late tail to policy depth, or an all-gather storm to stage-switch order.

## Build/runtime/toolchain

The browser application is deliberately dependency-free: static HTML, CSS, and native ES modules, with no build step. It can be served by any static server ([README lines 8-11](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L8-L11)); `index.html` loads `js/app.js` as a module ([index lines 135-145](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/index.html#L135-L145)). Browser APIs provide local persistence, URL state, clipboard sharing, SVG downloads, media-query dark mode, and direct DOM rendering.

Node supplies the other two execution surfaces. `node cli.mjs` runs a text interface over the same engine, while `node --test tests/` executes the native test suite ([README lines 84-86](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L84-L86)). CI pins Node 22, runs `node --test tests/engine.test.mjs`, and only then publishes the entire repository as a Pages artifact ([workflow lines 16-38](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/.github/workflows/pages.yml#L16-L38)). There is no package manifest, bundler configuration, or third-party runtime dependency in the pinned tree.

## Reusable design principles

These are design inferences grounded in the implementation, not claims made by external sources.

1. **Make the learner's work the canonical state.** An append-only action sequence plus replay makes undo, sharing, alternate frontends, and tests converge on one model ([engine lines 95-118](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L95-L118)).
2. **Centralize truth, multiply views.** One pure engine supports graphical interaction, terminal inspection, policy projection, and tests without duplicating legality rules ([README lines 88-95](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L88-L95)).
3. **Return structured failure causes.** Illegal placement carries a reason code and domain-specific message, enabling UI coaching from the same validator that protects correctness ([engine lines 156-182](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L156-L182), [lines 206-225](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L206-L225)).
4. **Automate repetition, stop at information.** Event-bounded auto-run removes mechanical warmup placement but stops at ties, bubbles, caps, and phase transitions—the moments where a learner has something to reason about ([engine lines 374-465](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L374-L465)).
5. **Progressively disclose power tools, not only content.** The curriculum controls when comparison, coaching, automation, editing, and sandboxing appear, keeping early cognitive load aligned with the current invariant ([app lines 9-23](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L9-L23)).
6. **Permit reversible invariant breaking.** Free edit supports global geometric experimentation while a live validator preserves a clear path back to executable state ([app lines 862-891](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/app.js#L862-L891)).
7. **Use multiple diagnostic projections of the same result.** Score, memory timeline, schedule recognition, critical path, idle explanation, playback, and side-by-side reference each answer a different “why” without changing the underlying schedule ([README lines 60-83](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L60-L83)).

## Limitations and open questions

- **It is a discrete teaching simulator, not a distributed runtime.** Time is integer slots, and operations have fixed durations selected from four tiny models ([engine lines 1-15](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1-L15)). There is no kernel variance, overlap model, network topology, collective contention, optimizer step, recomputation, or failure behavior in the pinned model.
- **Communication is mostly free.** The README explicitly says a dependency enables the next slot; no transfer operation consumes time ([README lines 96-100](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L96-L100)). FSDP all-gathers are counted as a communication proxy but are implicit and durationless ([engine lines 227-236](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L227-L236)). How lessons change with explicit communication resources remains open.
- **Memory is in abstract units.** Activations increment/decrement by one per local operation, and FSDP weights use a configurable per-stage scalar ([engine lines 121-145](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L121-L145), [lines 241-257](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L241-L257)). Uneven layers, tensor shapes, optimizer state, fragmentation, and rank-asymmetric footprints are not represented.
- **Reference is policy-relative, not globally optimal.** The ragged lesson explicitly admits a hand-crafted result that beats par ([levels lines 121-137](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/levels.js#L121-L137)). The repository contains feasibility helpers and greedy policies, but no exhaustive or mathematical optimizer; “beat par” and “optimal” must remain distinct.
- **Recognition is order-based.** Two schedules with identical per-rank operation order but different idle placement share a name; `exact` separately compares makespan ([engine lines 1146-1158](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1146-L1158), [lines 1196-1200](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/engine.js#L1196-L1200)). Whether this equivalence is pedagogically sufficient for all future policies is open.
- **The curriculum's paper attributions are not verified here.** `levels.js` contains external paper labels and links ([levels lines 1-10](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/levels.js#L1-L10)), but the source cap forbids following them. This study can verify repository behavior and authorial intent, not correspondence with those papers.
- **Accessibility and learning efficacy are unmeasured in-repo.** The source contains keyboard controls, dark mode, a colorblind-oriented palette claim, and multiple assistance levels, but no accessibility audit, telemetry, learner study, or pedagogical evaluation artifact in the pinned tree.
- **Licensing is unresolved.** No license file or detected license exists at the pin. This blocks confident code reuse even though architectural patterns can be studied.
- **The repository's README lags its own level list.** The README enumerates levels 1-9 and then describes a sandbox ([README lines 31-54](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/README.md#L31-L54)), while `levels.js` contains 11 levels including ZB-H2 and FSDP ([levels lines 173-205](https://github.com/ezyang/pipeline-parallelism-tutor/blob/4cf0b7247ee9334a3795af746dfd745fb5562601/js/levels.js#L173-L205)). The code and tests are the stronger source for current curriculum shape.
