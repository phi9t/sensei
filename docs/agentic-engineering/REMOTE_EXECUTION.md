# Remote And Sandbox Execution Policy

## Trusted-Code Mode

Use trusted-code mode for Sensei's reviewed source and ordinary local
development:

- one Git worktree per writer;
- ordinary user permissions;
- no direct `master` mutation;
- no destructive cleanup without explicit human authority;
- no committed credentials;
- deterministic checks through `scripts/agentic/*`.

A worktree is a concurrency boundary, not a hostile-code security boundary.

## Untrusted Or Generated Code Mode

Use untrusted mode when running code generated by an agent, an external
contribution, a benchmark task, or an unknown dependency. This host does not
have `bwrap`, so the current untrusted mode is fail-closed.

Do not claim hostile-code isolation exists on this host until a reviewed
sandbox wrapper is added and verified.

When a future Linux host provides `bwrap` and user namespaces, the supervisor
must stay outside the sandbox and the sandbox must:

- use a session-local source snapshot or shadow clone;
- avoid mounting the live base checkout read-write;
- avoid exposing the host Git object database to hostile code;
- mount the root filesystem and toolchain read-only;
- mount only the session workspace and explicit caches read-write;
- use a tmpfs `/tmp`;
- expose minimal `/proc` and `/dev`;
- hide `$HOME`;
- avoid mounting SSH agent sockets;
- avoid mounting `~/.aws`, `~/.config/gcloud`, `~/.kube`, Docker sockets, cloud
  credentials, or Kubernetes credentials;
- deny network by default;
- permit network only through explicit setup mode or a reviewed allowlist;
- capture stdout, stderr, exit status, timeout, resource use, and artifacts;
- have a trusted outer process compute and publish the final patch.

## SSH And GPU Hosts

When running over SSH on a shared GPU box:

- do not assume root, systemd, cgroup delegation, or control of the outer
  container;
- avoid global package changes;
- use session-local paths and caches;
- set process groups and timeouts;
- clean up only the current session's processes;
- never kill processes by broad name matching;
- do not use another user's GPU allocation;
- record host, GPU visibility, CUDA/runtime versions, and job PID.

## Remote Review CI

Remote roborev CI is disabled by default. Enabling it requires explicit human
authorization because it may comment on external repositories, consume model
budget, and require provider or repository credentials.

The same defaults are recorded for tools in `agentic.toml`: trusted execution
uses worktrees, untrusted execution fails closed on this host, and network is
denied by default for future sandbox profiles.

If later authorized, document:

- chosen CI runner;
- least-privilege permission model;
- secret owner and setup procedure;
- pinned release artifact and checksum policy;
- expected model cost and commenting behavior;
- a disposable-PR test before broad rollout.

Do not commit secrets. Do not auto-merge.
